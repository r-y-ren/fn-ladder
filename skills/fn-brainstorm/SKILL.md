# fn-brainstorm：卡壳创意（fn-ladder 发散器）

策略行不通时的创意发生器。**只产对话报告，不写任何文档**——它是发散器不是决策者；所有出口回到既有流程，门仍是用户的。

## 进入

带上卡壳点：哪个函数 / 哪个方案 / 哪条需求卡住了，已试过什么（blocked 原因、失败尝试的输出）。没有卡壳点就先问清。

纯粹想要创意思路（未卡壳）也可进入——此时**建议先跑 `/fn-review`** 拿现状事实（现有函数树、wired 状态、漂移清单）作发散底座，防止创意脱离现实；接力为 review（事实）→ brainstorm（选项，用户拍板）→ grill（定形落盘：演进模式追加 R 条目，或任务中走需求变更）。三棒只有 grill 写盘。

## 机制

1. **先定性**（决定出口回路）：实现级（某函数做不出）/ 结构级（函数树划错了）/ 需求级（要的东西本身有矛盾或想不清）。
2. **发散 ≥3 个替代方案，必须含一个激进选项**（推翻当前结构的那种——激进项的价值是暴露"当前前提可能整个不成立"）。
3. 每个方案三行快评：
   - 可行性：对照现有函数树与需求约束；
   - 代价：回退到哪个阶段、要改哪些文档、丢弃多少已 wired 成果；
   - YAGNI 检查：这个方案是否在解决一个不存在的问题 / 顺带造没被需要的东西。
4. 给**推荐 + 理由**；用户选定后才动——发散器永不替用户拍板。
5. 选定后**指回对应回路**：
   - 实现级微调 → fn-implement 批内继续；
   - 结构级 → fn-divide 快速通道改责任文档；
   - 需求级 → fn-grill 需求变更；
   - 激进重构 → `/fn-refactor`（存量重来的正式通道）；
   - 绕过障碍 → 回批间门，由用户明确授权、**由 fn-implement 记入 batches.md 变更记录**（本技能不落盘）。

## 红旗（出现即停）

| 念头 | 现实 |
|---|---|
| "这个方案明显最好，我直接改了" | 发散器不落盘；选定方案走回路执行 |
| "再想想别的"永不收敛 | ≥3 方案 + 推荐之后必须交用户裁决 |
| "激进项太蠢，不列了" | 激进项是 mandatory——它的职责是质疑前提，不是被选中 |
