# fn-analyze：结果分析与改进提案（fn-ladder 数据驱动改进入口）

把运行结果数据与代码实现放在一起分析，产出**到函数级**的改进提案。三棒的专用合体：review 的结果轴扩展 + brainstorm 的方向发散 + grill 的定形出口。**分析、不实施**——同 on-ramp 哲学，出口交回单个技能。

它管的是验收的另一半：功能对不对归五阶段，**效果好不好归这里**——改了、验收通过了、分数没涨的"合法假完成"由效果闭环拦截。

## 进入检查

- `fn_docs/` 与代码在（无 → 指回 `/fn-grill` 或 `/fn-refactor`）。
- requirements.md 外部依赖节有**结果数据源**条目（拉取命令、格式与存放）。**登记即用**：跑批中途新出现的数据源（语料/接口/工具）当场在外部依赖节追加一行（名称 / 获取命令 / 抓取日期 / 用途）即可投入使用，不回 `/fn-grill`；登记完备性由 fn-close 验收时统一核。

## 机制

1. **拉数据（派子代理，隔离大输出）**：子代理按数据源条目拉取 → 快照存 `fn_docs/results/<日期>-<说明>.<ext>` 随 git 留痕 → 按**子代理结论契约**回主会话。拉取命令必须可复跑。
   **子代理结论契约（四段，全 fn-ladder 子代理通用）**：①判据判定表（判据 | 读数 | 过/不过）②关键读数（结论所需最小数字集，标来源字段）③异常与限界（错误/样本缺口/混杂/置信声明）④建议（可行动项分级）。主会话只收四段、不收原始转储；不合四段的报告退回重写。
2. **三轴分析（主会话）**：
   - **结果轴**：统计摘要找现象——胜率变化、分布偏移、断崖、方差、同上快照对比；
   - **代码机械轴**：插件根 `scripts/fn-check.sh` 与 `scripts/fn-doc-lint.py`（先排除"数据差是因为代码坏了"）；
   - **职责关联轴（核心，条件适用）**：现象 → 责任文档职责 → 函数——沿"哪个函数的职责覆盖这个行为"定位嫌疑人，不许跳过职责链直接猜。**适用于软件缺陷类现象**（行为错/性能差/崩溃）；
   - **证据强度轴（情报/评测类现象适用，替代上轴）**：信号来源（一手实测/二手自报/观察性相关）→ 样本量与覆盖 → 混杂与反例 → 可证伪性（受控对照在哪）→ 口径（同块/同窗才可比）。现象没有函数嫌疑人时（对手换血、榜面漂移、环境噪声），不许硬套职责链——先按本轴定证据等级再定行动。
3. **改进提案**（发散纪律同 fn-brainstorm：≥3 个方向、必含一个激进项），每条五字段：

   ```
   ### P1 <一句话方向> [优先级]
   - 现象：数据证据（快照对比的具体数字）
   - 假设：定位到函数或证据链——软件缺陷类引责任文档职责（"X 的职责是…，而数据显示…"）；情报/评测类按证据强度轴给结论链（来源/样本/混杂/可证伪性）
   - 改进方向：做什么（不写实现细节）
   - 预期信号：改完后结果数据应出现什么变化 ← 数据版验收方式的种子
   - 分流：参数/逻辑级（[改造] 现有函数）vs 结构性（回 fn-divide）
   ```

   每条提案**同时登记进 `fn_docs/analyses/registry.jsonl`**（一提案一行 JSON：id / date / phenomenon / target / expected_signal / status / scored_in）——机器可读的唯一提案真值，id 形如 `<报告哈希前6位>-<n>`。

4. **效果闭环打分（铁律，由 `scripts/fn-score.py` 承载）**：跑打分工作台（列 pending 提案与最新 results/ 快照）→ 按预期信号判定 → `--set <id> <achieved|missed|reversed>` 落 registry。**打分表不许手翻旧文档手写**——脚本出差分，判定归人。未达成或反向 → 建议转 `/fn-brainstorm`（方案失效换思路）。
5. **报告落盘** `fn_docs/analyses/<YYYY-MM-DD>-<内容SHA1前6位>.md`（写盘后计算定名——两会话并发天然不撞，废除人肉数序号）；必含"上次快照 vs 本次"对比节与打分表（贴 fn-score.py 工作台输出）。

## 冲刺模式（v1.6）

用户**显式授权**开启（"进入冲刺模式"或等义明确表述），授权时必须钉死两件事：**范围**（如"这批臂全测完"）与**退出条件**。开启后按技能族既定顺序流水自动推进、**步间免确认**：

- **顺序不许自创**：只按各技能既定机制的步骤走，不合并、不跳步、不重排；每步完成即 `fn-commit.sh` 落痕（JOURNAL 行照写）。
- **纪律不降**：判据先行、核验贴输出、效果闭环照跑照贴；提案仍逐条登记 registry。
- **不可逆动作仍需明批**：外发/对外提交（比赛提交、上传等——非 git 提交，git 落痕照走 fn-commit）/删除/覆盖既有成果——无论冲刺与否停下等用户显式批准（外发再过 fn-close 外发终检三验）。
- **退出即停**：范围打完 / 退出条件满足 / 用户叫停 / 判据熔断（同项重试超限）→ 停下报告，回到常规门口节奏。门口与批间门在冲刺范围内降为"门不停人"：过门自动续，门的核验照跑。

## 轻量线（v1.6，路由；规范见 FN-LADDER.md 轻量线节）

本技能的提案**分流为"参数/逻辑级"且用户选定** → 走【轻量线】：快问（目的一句话+验收一条）→ 实现+核验 → `fn-commit.sh` 落痕——本技能轻量线分支内**可实施该参数级改动**（全量线下仍不实施）。结构性提案照旧指回 `/fn-grill`。**报告首行必须显式标注线别**（【全量线】/【轻量线】）。

## 出口

提案逐条呈用户裁决（只报事实与建议，判定归用户）。用户选定提案后**停**，显式提示两项：**下一步命令 `/fn-grill`**（演进模式开 R 条目，验收方式从选定提案的"预期信号"命令化或写成可观察判据），或**修订本分析**（补数据、换方向重析）；用户未显式选择前不推进。本技能默认不实施任何改动（**轻量线分支例外**，见上）。冲刺模式下出口改为"本步完成即续下一步，直至退出条件"。

## 红旗（出现即停）

| 念头 | 现实 |
|---|---|
| "分数降了，直接改代码吧" | 全量线下只分析不实施——提案过 grill 才能动代码；参数级改动走轻量线且须用户选定提案 |
| "冲刺中我说了算，跳过判据" | 冲刺只免步间确认，不免判据；顺序照技能既定步骤，不可逆动作照停 |
| "现象很明显，不用引数字了" | 现象必须有快照对比的具体数字，防印象流分析 |
| "这个函数看起来可疑" | 定位必须经责任文档职责链，不许跳过关联直接猜 |
| "上次提案就不打分了" | 效果闭环是铁律——不打分的改进循环是盲飞 |
| "打分表我顺手整理一下" | registry + fn-score.py 是真值，手写表必漂移 |
