# fn-refactor：存量项目重构入口（fn-ladder on-ramp）

让存量项目经一次完整 fn-ladder 任务重构进 `fn_work/` 标准结构。核心纪律：**用户先讲、代码后查、行为不自动变需求、无安全网不动结构**。每阶段完成停下确认并给出建议。

## 阶段一：第一轮 grill——用户先讲

- 请用户口述项目的大致工作流程与功能；**README.md 的素材只来自用户说明，禁止先读代码反推**（叙述一旦被代码污染，bug 会被当成"本来就该这样"）。
- 机制同 fn-grill（轮次/前沿/推荐答案/通俗解释）。
- 产出：README.md 草案（用户向）。

## 阶段二：代码审查——差距与遗漏

- 全量分析实际实现，对照用户描述产出：
  - **行为清单**：程序实际做了什么（逐条，含可疑项标注）——这是事实，归分析。
  - **差距表**：用户没提到的细节与相关实现。
- 旧代码此阶段起**只读**（快照测试文件除外），验收前一个字节不动。

## 阶段三：第二轮 grill——行为裁决

- 行为清单逐条请用户裁决：**有意保留 / 是 bug 要修 / 该丢弃**。裁决归用户。
- **代码行为绝不自动变成需求**——与 fn-merge 的"禁止面向结果生成需求"同一条原则。
- 产出：requirements.md——保留项=需求条目；bug 修复=条目（验收方式=能让旧代码失败、新代码通过的快照反例）；丢弃项=范围外+理由。

## 阶段四：行为安全网（快照测试）

- 对全部"保留"行为的关键入口建 characterization 测试（输入输出对照固化），**对旧代码跑绿**。
- 没有安全网禁止进入重构——纯搬迁禁止。快照暂存 `snapshot_tests/`，重构实施时迁入 `fn_work/tests/`，成为重构任务的 tested 判据。

## 出口：本技能到快照安全网为止

- 两轮 grill + 快照安全网即本技能的**全部职责**；此后由用户显式逐步调用正常流程的单个技能，本技能不代跑：`/fn-divide` → `/fn-scaffold`（快照测试此时迁入 `fn_work/tests/`）→ `/fn-implement` → `/fn-close`。
- 产物（README.md、requirements.md、snapshot_tests/）经用户确认后**停**，显式提示两项：**下一步命令 `/fn-divide`**，或**修订本步骤**；用户未显式选择前不推进。
- 流程终点说明（供后续阶段参照，非本技能动作）：`fn_work/` 新结构从零长出；fn-close 验收通过后**旧代码整体删除**（git 历史留痕）。

## 红旗（出现即停）

| 念头 | 现实 |
|---|---|
| "先扫一遍代码再问用户" | 顺序反了——用户叙述会被代码实现污染 |
| "这个行为代码里有，直接进需求" | 代码行为只提供事实，需求必须经用户裁决 |
| "结构简单，直接搬不用快照" | 无安全网的搬迁 = 行为悄悄变掉的温床 |
| "分析时顺手修个小 bug" | 旧代码验收前只读；bug 修复是重构任务里的需求条目 |
