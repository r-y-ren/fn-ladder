# fn-implement：分批自底向上实现（fn-ladder 第④阶段）

按批次自底向上逐函数实现。**本阶段文档产出物是 implementation 三文档**（`fn_docs/implementation/` 下 `batches.md` 批次表 / `functions.md` 函数大表 / `history.md` 历史表），本阶段是它们唯一的写入者；**responsibility.md 与 requirements.md 只读**。

## 进入：先对账，再干活

1. 检查前置：`responsibility.md` 在、桩代码在位。缺 → 停，指回前序阶段。
2. **轻量对账（派对账子代理）**（新会话/压缩/中途接手必做）：派子代理运行插件根 `scripts/fn-check.sh`（本技能目录上两级，用法见脚本头）并对照 functions.md 函数大表，主会话只收结论报告——对账输出不进主上下文，子代理无立场偏见。**对不上先修文档再干活**，防止上个会话的谎报传染。
3. 三文档不存在 → 先做批次计划（见下）；存在 → 从真实位置继续。
4. **中断恢复**：突然中断的批次必仍在批次表（未入历史表）→ 直接按该批次重做；对账中证据可复跑（commit 在、核验命令重跑通过）的函数不必推倒，其余按其标注状态重做。批次不会因中断丢失或被跳过。

## 批次计划（垂直切片）

- 每个顶层函数的子树一批：自底向上实现完该子树 → 顶层函数 wired = 一个功能口可验收，每批都有可验收增量。
- 单批函数数上限 8，超限则子树内部按层切半。
- 批表门口由用户选执行档位：**主会话连续 / 子代理逐函数**（单批 ≥6 函数建议子代理档——每函数带紧凑提示：职责块 + 桩位置 + 核验命令，派子代理实现；主会话只做调度、贴输出、改状态、把门）。
- 批次表 + 函数级清单写盘后呈现，**停在门口等用户批准**。

## 批内循环

取**依赖已就绪的最深**未完成函数（自底向上 = 实现某函数时它调用的下层全部就绪，单测可真跑）：

1. `implemented`：桩被真实实现替换。
2. `tested`：叶子函数必须自有单测且绿；中上层可标"上游覆盖"并指向具体测试名。
3. `wired`：静态调用点存在（grep/ast-grep 可验）；顶层入口函数实跑一次、有可观察输出。
4. **每次改清单状态前，先跑核验命令、把输出贴进证据列，绿了才许改**。
5. commit：`fn(<函数名>): wired`，同 commit 包含 implementation 三文档的变更——git log 成为第二进度真值（用户接管 commit 则跳过）。分支默认不开、在当前分支做；需隔离时由用户在 fn-grill 门口声明，分支名 `fn-<日期>`。
6. 下一个函数。批内连续推进，用户可随时插话。
7. 卡死（同一函数两轮仍无法实现或测试不过）→ 清单标 `blocked` + 原因，跳到下一个不依赖它的函数；批间门集中报告 blocked 项由用户裁决（改需求 / 回 fn-divide 换方案 / 授权绕过）。**禁止静默跳过。**

## 批间硬门

每批验收点达成 → 先派**评审子代理**双轴审查本批 diff（规格轴：对照责任文档的职责/签名意图/树外改动；标准轴：桩标记/命名/目录规则；用户说"免审"可跳过），报告随汇报附上 → **停，显式提示三项：继续下一批 B<N>（说"继续"即可）/ 修订本批产物 / 裁决 blocked 项**；用户未显式选择前不推进。批间是天然会话边界：可 `/clear` 或压缩后新开会话，靠轻量对账无缝续批。
预授权例外：用户字面明确"剩下的批次不用等我"才可连做，模糊的"继续"只解锁当前批次；批间报告照发。

## 漂移三则（防静默偏航）

- **签名微调**（参数名、可选参数）：代码即真值，responsibility.md 的签名意图本就是意图级描述，不用改它；在 batches.md 变更记录登记即可。
- **结构性变化**（函数增/删/拆/并/职责或调用关系变化）：**停**，回 fn-divide 改 responsibility.md（可走一次确认式快速通道），回来更新清单再继续。
- **计划外现有代码（树外）改动：未经批准一律禁止**（含机械清理）。发现 → 作为新任务加入批次表下一批次、注明"新增改动" → 批间门经用户批准后随批实施。每步责任必须分明。

## 需求变更

停下 → 变更经 fn-grill 语义记入 requirements.md 变更记录 → fn-divide 重算受影响子树 → 回本阶段更新清单。

## 红旗（出现即停）

| 念头 | 现实 |
|---|---|
| "这个函数太简单，跳过测试" | 四态无捷径，简单函数的测试最便宜 |
| "先都实现完再一起测" | 攒批测试 = 假完成温床 |
| "新函数顺手直接写了" | 未进责任文档的函数 = 死代码候选，必须回 fn-divide |
| "状态我记得，不用对账" | 对话记忆不可靠，盘上核验才算数 |

全员 wired → **停，显式提示两项：下一步命令 `/fn-close`，或修订**。
