# fn-review：只读审计（fn-ladder 随叫随到）

任何时候可调的独立审查。**只读一切（代码 + 全部 fn_docs 文档 + git 历史），只产对话报告，不写任何文件**——审计不是流程阶段，没有文档所有权。若派子代理执行，只带精制上下文（文档路径、代码路径、上一验收点 SHA），**不带会话史**。

## 进入检查

`fn_docs/` 与代码在。无 → 还不是 fn-ladder 项目，指回 `/fn-grill`（新项目）或 `/fn-refactor`（存量项目）。

## 双轴审查

### 机械轴（先跑，脚本与 git 承载）

1. 插件根 `scripts/fn-check.sh`（本技能目录上两级）：残留桩 / 全量测试 / tests 镜像。
2. 插件根 `scripts/fn-doc-lint.py`：文档结构、矩阵双向、死代码。
3. **git 对账**：`git log` 的 `fn(...)` 提交序列 vs functions.md 状态列——commit 说 wired 而表没记（或反之）= 漂移。
4. **手动改动扫描**：上一验收点之后的提交里，凡非 `fn(...)` 前缀且触碰 `fn_work/` 的 = 绕过流程的改动，逐条列出。

### 规格轴（后做，逐函数抽查）

- 对照 responsibility.md 做**职责重写规约验证**：凭"职责 + 签名意图"能否复现现实现。抽查重点：最近变更的函数、blocked 过的函数、`shared/` 里的函数。
- 命名与结构：代码函数名 vs 责任文档树、目录规则（顶层函数文件夹 / shared / tests 镜像）。

## 报告（对话呈现，不落盘）

- 每条发现**先核实存在再报告**（证据 = 命令输出行或 文件:行），分级：**Critical**（功能性与需求不符/死代码/测试假绿）/ **Important**（文档漂移/绕过流程的改动）/ **Minor**（命名、结构建议）。
- 每条指回对应回路：文档漂移 → 轻量对账修正；结构性 → fn-divide 快速通道；需求级 → fn-grill；手动改动 → 进演进周期时裁决纳入或回退。
- 结论只报事实："本轮发现 Critical x / Important y / Minor z"——**健康与否由用户判定**，审计不宣布健康。

## 红旗（出现即停）

| 念头 | 现实 |
|---|---|
| "发现个小问题，顺手修了" | 只读纪律：审计者不修改，修复走对应阶段 |
| "看起来像漂移，报了吧" | 先核实存在，证据不齐不报 |
| "全部正常，项目健康 ✓" | 只能报"本轮未发现"，判定归用户 |
