# Spec: v2.2.2 收尾修复（模板同构 / 降级优先级 / 实槽对齐 / 登记精度）

- 日期：2026-10-13
- 来源：code-review 第四轮（Standards 0 硬违规 + 5 判断题；Spec 2 半逐字、0 相悖）

## Problem Statement

第四轮审查确认无硬违规，但留有同构与精度毛刺：两份冻结模板在治理句/攻击向量/配额形态/分级注释上漂移；INSTALL 两种降级给出两种会话归属未定优先级；fn-close 白名单头注与其实际槽位不符；退役登记的新词形态与活文本不逐字、修复规格自述"零残留"字面过强。

## Solution

场景中立句补齐两模板同构（走查侧配额落数字形态"每条命令/功能段至少一条"）；fn-implement 输出补分级注释对称；INSTALL Class 4 声明"冻结模板降级段优先"；fn-close 头注白名单按实槽改写（审查对象与 claims 为固定文本、无槽）；退役登记新词归一为六要素权威形态；④ 索引补"≥2"；吸收规格注记走查适配形态已认可。

## User Stories

1. 作为模板维护者，我希望治理句"派发方不得供给"与攻击向量括注在两份模板同构，以便场景差异只留在适配句。
2. 作为走查执行者，我希望配额是数字形态（每条命令/功能段至少一条），以便可核销。
3. 作为读者，我希望 fn-implement 输出分级带注释（阻断/误导与逻辑/体验），以便两模板对称。
4. 作为安装代理，我希望 Class 4 声明冻结模板降级段优先，以便两种降级不再打架。
5. 作为审计者，我希望 fn-close 白名单头注与其实际槽位一致（固定文本不冒充槽位），以便白名单真的可执行。
6. 作为维护者，我希望退役登记新词与活文本权威形态逐字、"零残留"表述限定为活文档，以便精度注记自洽。

## Implementation Decisions

- fn-close 功能抬杠节：补"派发方不得供给"、攻击向量括注（功能缺失/行为不符/边界失守/与承诺目标不符——走查适配）、"每条命令/功能段至少一条"数字配额。
- fn-implement 输出节：分级补注释"Critical（阻断）/ Important（误导与逻辑）/ Minor（体验）"。
- fn-close 白名单头注改写："白名单槽位：工作目录 / 测试运行方式 / 功能要求出处 / 输出契约补充项（可选）——审查对象与 claims 在走查中为固定文本（user-guide 全文即审查对象与主张），无槽"。
- INSTALL Class 4（英中）：补"通用降级与冻结模板降级段冲突时，以冻结模板降级段为准（对抗审查/走查场景）"。
- release.sh 退役条目新词侧归一为"临时件只落 /tmp、仓库零写入"（六要素权威形态）。
- review-fixes 规格"零残留"表述改"活文档零残留（CHANGELOG 已发布历史条目按精度惯例豁免）"。
- FN-LADDER ④"每方向自拟假设"补"≥2"；吸收规格注记走查适配形态（claims 指针句、配额句）已认可为合法适配。
- fn-quick 指针详略差判定接受（指回中枢）。
