# Spec: 参考资料显式询问与登记（reference intake）

- 日期：2026-10-09
- 来源：grilling 一轮定案（主干用户拍板；Q1 = 独立九节；Q2 = fn-close ⑥ 纳入同款核对）
- 目标版本：v2.2.1（发版时机待用户点头）

---

## Problem Statement

任务开工时用户常已把参考文件（设计稿、旧文档、样例数据）放在 `docs/` 等目录下，但技能对此一无所知：只能靠用户记得主动说明，忘了就静默缺料——与 fn-ladder 一直在治的"靠记忆"同类失效。

## Solution

fn-grill 开工时**显式问一次**"有无参考资料"，把答案登记进 requirements.md 新增的"参考资料"节（指针登记、不复制内容）；参考资料是**访谈输入不是真值**，冲突归用户裁决、过期标"历史参考"不删；fn-close ⑥ 同款核登记完备性。不自动扫目录。

## User Stories

1. 作为用户，我希望开工时被显式问一次"有无参考资料"，以便不靠自己记得提醒。
2. 作为用户，我希望"无"也被记录，以便下次接手不重问。
3. 作为用户，我希望参考资料只登记指针（路径+用途+以何为准+日期），以便内容不被复制出第二份漂移源。
4. 作为用户，我希望多份资料冲突时停下由我裁决，以便技能不自作主张。
5. 作为用户，我希望过期资料标"历史参考"而非删除，以便输出全留可追溯。
6. 作为用户，我希望参考资料被明确定位为访谈输入而非真值，以便需求真值仍只有 requirements.md。
7. 作为执行代理，我希望参考资料登记在独立一节，以便不与"外部依赖（登记即用）"语义相混。
8. 作为审计者，我希望 fn-close 终检核登记完备性（登记表对得上实际文件、过期有标注），以便登记约定不烂尾。
9. 作为中途接手者，我希望续作不重问（登记表即真值），以便对账顺带核、不折腾。
10. 作为使用者，我希望轻量线/merge 不受影响，以便短路径不变慢。

## Implementation Decisions

- **询问落点**：fn-grill 进入检查——全新任务与功能演进分支各问一次；续作/中途接手不重问（登记表即真值，对账顺带核）；轻量线不问。问句固定："有无参考资料（`docs/` 等目录或用户指定路径）？"——有 → 用户圈定本期范围 → 登记；无 → 记"无"。不进必问八条（性质是输入登记，不是需求语义）。
- **登记落点**：requirements.md 新增顶级节"参考资料"（八节升九节，置于术语表与需求条目之间——素材在前、条目在后）。登记表字段：路径 / 用途 / 以何为准 / 登记日期。指针不复制内容（handoff 指针原则）。
- **语义边界**：参考资料是访谈输入不是真值；与访谈结论冲突 → 停请用户裁决；过期 → 标"历史参考"不删；`docs/` 不在 fn_docs 目录契约内、所有权归用户，技能只读登记指针。
- **终检闭环**：fn-close ⑥ 目录清点纳入参考资料登记完备性（登记表与实际文件对得上、过期有标注），与外部数据源登记完备性同款。
- **机械同步**：fn-doc-lint 节名校验表加"参考资料"（warn 级，同八节既有粒度）；README 双语任务产物树"八节→九节"并提一句开工询问；FN-LADDER 脚本描述与所有权表 requirements 行同步。
- **不自动扫目录**：防陈旧/无关文件被当需求喂入（过度供给），且 docs/ 所有权归用户——显式登记兼顾"不忘"与"不越权"。

## Testing Decisions

- 好测试 = 只测外部行为：lint 对缺节给出 WARN、selftest 断言该 WARN 出现；不测措辞。
- 接缝不变：fn-doc-lint（节名 warn 表）+ fn-selftest 加一条断言（缺"参考资料"节应告警）。
- 先例：fn-doc-lint 既有八节 warn 表、fn-selftest 七断言。

## Out of Scope

- 自动扫描/索引 docs/ 目录。
- 轻量线、fn-merge、fn-refactor 专项改动（refactor 经其 grill 轮次自然覆盖）。
- 必问清单扩成九条（性质不同，不动"必问八条"）。
