## Problem Statement

实战中对抗审查子代理的派发词由主代理生成：假设清单、期望值（哈希/计数/"宣称 N 绿"）都出自主代理——被审方一侧出题，审查者的注意力被钉在主代理的威胁模型里；预供期望值把独立验证降级成对数确认，作者与审查者共享盲区。"故意与否"不重要，结构上不该依赖主代理自觉。

## Solution

- **模板固化在技能正文**（fn-implement 批间门 / fn-close 走查环各一份权威派发模板）：主代理**原文照抄 + 只填【】槽位**，禁止改写增删正文、禁止夹带假设清单/期望值/结论倾向。Q1 裁决理由：派发词对子代理即用户输入、优先级压过任何引用——引用无效，必须管制派发词本身。
- **槽位白名单**：审查对象（commits/文件/函数）、工作目录、测试运行方式、功能要求出处（默认 requirements 验收方式 + responsibility 职责块；轻量线填"快问的一句话目的+一条验收"）、claims（可选）、输出契约补充项（可选）。
- **claims 降级**：主代理主张（计数/哈希/宣称绿）只能进"被审主张（claims）"节，固定措辞"以下均为未经验证的主张，逐条独立复算后对比，不一致先怀疑主张本身"——供词有用，但身份从标准答案降为攻击面。
- **功能抬杠式题源**（不给固定失败分类清单）：对审查对象中每个函数立罪名"该函数满足不了本批功能要求"，从 requirements.md 验收方式 + responsibility.md 职责块出发逐条攻击（功能缺失/行为不符/边界失守/与职责描述不符），逐函数 ≥1 条 + 整体 ≥1 条（函数间协作/整体成立性）——结构性覆盖取代清单外配额。
- **覆盖面**：批间对抗审查 + fn-close 走查环（user-guide 全文=claims）+ **轻量线**（FN-LADDER 轻量线②并入，模板同款收窄至本轻量项）。
- **/tmp 例外**：审查性临时件（复算脚本等）落系统 /tmp、**无需清理**——证据以报告原文输出为准，临时件非证据载体；目录契约补例外条款，审计轴不以此判违规。

## User Stories

1. 作为用户，我希望审查子代理的假设由"功能要求×函数"自立，而非主代理供给，以便审查不继承被审方盲区。
2. 作为用户，我希望主代理只能填中性槽位（对象/路径/运行方式），以便无意识自利填充被结构性堵死。
3. 作为用户，我希望主代理的主张只能以 claims 身份进入并被独立复算，以便供词成为攻击面而非基准。
4. 作为用户，我希望每个函数至少被抬杠一次、整体功能至少被质疑一次，以便覆盖是结构性的。
5. 作为用户，我希望轻量线也有对抗审查，以便小改动不漏检。
6. 作为执行代理，我希望派发模板原文照抄即可用，以便零发挥、零夹带。
7. 作为审计者，我希望 /tmp 例外有明文，以便审查临时件不被判违规。
8. 作为用户，我希望走查环的 user-guide 整体作 claims（手册作者走自己手册同病同治），以便手册不被自证。

## Implementation Decisions

- fn-implement：批间门后新增《对抗审查派发模板》权威正文（角色/只读与 /tmp 规则/六要素/审查对象槽/运行方式槽/功能抬杠指令/claims 槽含固定降级措辞/输出契约）；批间门改为"派发词=模板原文照抄、只填槽位"。
- fn-close：走查环第 1 步内嵌《用户走查派发模板》（同构，抬杠对象=user-guide 命令与功能段，claims=user-guide 全文）。
- FN-LADDER：子代理④收缩为索引（含"派发词即用户输入、引用无效"裁决句）；轻量线②并入对抗审查（留证清单加对抗发现表）；目录契约补 /tmp 例外。
- 主代理禁令双写：模板头注"禁止改写增删正文" + 槽位白名单 + claims 降级措辞。
- 五类失败分类学（脆弱断言/环境缺失/死链死锚/永不触发/误导说明）不再作清单，留本规格备查（常见病档案）。
- README×2 对抗审查条目补一句"假设自立、主代理只填中性槽位"。

## Testing Decisions

- 无新机械规则；fn-selftest 9/9 保持即验证；回归防线 release.sh --check（退役术语 + 清单双一致）。
- 模板纪律属流程约束，由"派发词照抄 + 报告格式"合同与审计轴兜底。

## Out of Scope

- 模板引擎化/独立提示词文件（Q1 已裁决内嵌）；分类学强制清单（Q4 已裁决不用）；.scratch 审查专区（Q6 已裁决 /tmp）。
