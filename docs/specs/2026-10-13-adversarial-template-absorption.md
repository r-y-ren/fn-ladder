- 日期：2026-10-13
- 来源：用户展示实战第二版对抗派发词（独立长出"零假设供给/claims 指针化/全错立场"）+ grilling 四题定案（Q1 全收 / Q2 并列双节 / Q3 双重配额 / Q4 融合措辞）
- 目标版本：并入 v2.2.2（未发同车）

## Problem Statement

第二版实战派发词在对抗姿态、claims 指针化、校验工具扩展上优于现行模板，但仍是手搓（无结构下限保障）；现行模板缺广度覆盖骨架（维度漏审）、缺逐函数之外的正交约束、claims 槽未指明指针优先。

## Solution

吸收七元素进两份冻结模板：①四正交方向覆盖骨架 ②每方向 ≥2 自拟假设 ③claims 指针优先 ④全错初始立场 ⑤声誉激励句（配防虚报句）⑥校验工具在审列扩展（假绿形态清单/git 档案/commit 哈希）⑦假设数量不设上限。与功能抬杠**并列双节**（深度=逐函数、广度=四方向），双重配额；轻量线收窄（方向骨架保留不设条数）。

## User Stories

1. 作为用户，我希望模板吸收第二版的全错立场（"所有宣称默认为假，举证责任在宣称方"），以便对抗姿态有法理句压住滑坡。
2. 作为用户，我希望四正交方向（规约一致性/假绿探测/三方档案/运行时真值）进模板作覆盖骨架，以便维度漏审被结构性堵住。
3. 作为用户，我希望双重配额（每函数 ≥1 + 每方向 ≥2 + 整体 ≥1），以便函数漏审与维度漏审双防。
4. 作为用户，我希望 claims 槽指明"指针优先于原文"，以便审查者自己取供词。
5. 作为用户，我希望声誉激励与防虚报并存（不成立也要贴否证输出），以便多抓而不虚报。
6. 作为用户，我希望校验工具在审列扩展到 git 档案与 commit 哈希，以便档案层谎报进攻击面。
7. 作为轻量线执行者，我希望配额收窄（方向骨架不设条数），以便小项不被仪式拖垮。

## Implementation Decisions

- 两份冻结模板（fn-implement 批间 / fn-close 走查）同构更新：六要素"对抗假设"换融合措辞（文档是错的/命令会失败/测试是假绿/档案与代码不一致——所有宣称默认为假，举证责任在宣称方）；"校验工具在审列"扩展（假绿五形态：断言恒真/mock 过度/skip 掩盖/正则空洞/时序巧合；git 档案与盘上字节；commit 哈希指向）。
- 新增《覆盖骨架》节与《功能抬杠》并列：走查模板四方向适配为（a）手册承诺一致性（b）假绿探测（c）手册/档案/代码三方（d）运行时真跑。
- 配额：批间与走查=每函数/每条命令 ≥1 + 每方向 ≥2 + 整体 ≥1；轻量线=每函数 ≥1 + 整体 ≥1（方向骨架保留不设条数，注记在 FN-LADDER 轻量线②）。
- claims 槽说明加"优先填指针（主张所在处：文档/行/commit），主张原文可少填或不填"。
- 骨架节尾固定双句："假设数量不设上限；你的声誉来自抓到别人没抓到的问题，而不是复述宣称——但不成立的假设必须贴否证输出，禁止为凑数虚构发现。"
- FN-LADDER ④ 索引句补"+ 四正交方向覆盖骨架"。

## Testing Decisions

- 无新机械规则；selftest 9/9 与 release --check 保持即验证（模板为冻结文本，合同由照抄纪律与报告格式约束）。

## Out of Scope

- 模板引擎化；分类学病灶清单（已裁决不设）；声誉机制的自动化评分。

## Further Notes

- 第二版派发词的"claims 指针化（宣称散布在：…）"被视为比 claims 槽原文更优的形态，已吸收为指针优先规则。
- 与上游治理规格并读：本篇是模板内容演进，治理结构（冻结/槽位/照抄）不变。
- 走查模板的适配形态（claims 指针句改写、配额句"每条命令/功能段至少一条"）经第四轮审查认可为**合法适配**，非逐字偏差。
