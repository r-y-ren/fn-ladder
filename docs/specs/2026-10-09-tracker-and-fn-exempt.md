## Problem Statement

在全量线（fn-implement）执行中，AI 的步骤纪律只活在技能文本和对话里：盘上没有步骤级进度账本，"走到哪、凭什么说做完"全凭模型自述。真实失效有三类：

1. **跳步/漏步**：进入五步、批内七步被跳过或合并（"太简单""我记得做过了""最后一起测"）。
2. **档案 no-op 静默漂移**：状态更新脚本有 no-op 缺陷，12 批状态从未真正写进 functions.md 才发现（代码与测试一直全绿，档案侧静默漂移）。
3. **豁免口失控**：免审、冲刺模式、预授权连做、用户接管 commit 等豁免混杂在各命令段落里，随口一句话就生效、不留痕，审计无从还原。

会话压缩或中途接手后，进度只能靠对账子代理重建；已完成的步骤可能被重做，未完成的步骤可能被跳过。

## Solution

1. **引入落盘的步骤级执行账本 tracker**（implementation 第四文档）：每步执行内容强制"预告 → 执行 → 证据 + 读回"三段式显示在 tracker 并在对话中逐步渲染；执行以"第一个未勾行"为唯一导航，完成行由硬门脚本在核验通过后写入（失败不记账），写后必须读回——no-op 类事故当场暴露。
2. **豁免收束到单一命令 /fn-exempt**：五处豁免口从原命令中删除，统一由 fn-exempt 承载；口头豁免必须先由代理明确宣告"开始执行 /fn-exempt"再触发流程并记账，**无记账 = 无豁免**；证据类纪律永不可豁免。
3. **配套纪律升级**（非纯增量）：总纲第五不变式升级为"步骤纪律 = 按 tracker 步骤执行"；fn-implement 执行措辞改写；fn-doc-lint / fn-review / fn-close 机械与审计轴扩展。

## User Stories

1. 作为用户，我希望每步执行前在 tracker 里看到该步的目标/动作/预期，以便随时知道 AI 正在做什么、应该产出什么。
2. 作为用户，我希望每步执行后 tracker 里留下证据（命令输出原文或读回的改后内容），以便判断"做完"是真是假。
3. 作为用户，我希望 tracker 在对话中每步同步渲染最新表，以便不打开文件也能看到进度。
4. 作为用户，我希望"下一步"永远是账本第一个未勾行，以便 AI 的推进顺序可见且不可乱。
5. 作为用户，我希望跳步（如跳过 tested 直奔 wired）在账本结构上不可能静默发生，以便七步纪律不再依赖模型自觉。
6. 作为用户，我希望 AI 对每种跳步念头有预写的反驳（借口对照表），以便它不会自我合理化跳步。
7. 作为用户，我希望状态更新脚本失败时什么也不记账，以便"跑了脚本"不再等于"已记账"。
8. 作为用户，我希望任何写入后必须读回贴出改后内容，以便 no-op 静默漂移当场暴露。
9. 作为用户，我希望 12 批 no-op 那类事故在第一批就被拦截，以便档案漂移不再累积。
10. 作为用户，我希望跨会话/压缩后 AI 凭账本身份行与 git log 恢复到第一个未勾行，以便接手不重做已完成步骤。
11. 作为用户，我希望账本与 git 压倒记忆——AI 不再以"我记得进度"为据，以便恢复可信。
12. 作为用户，我希望偏离计划（签名微调、计划错误）以 Ruling 行留痕（决策+原因+代价），以便偏离可见且可审计。
13. 作为用户，我希望未记账的偏离被审计轴点名，以便私自决策无处藏身。
14. 作为用户，我希望豁免全部收束到 /fn-exempt 一条命令，以便豁免与日常命令彻底分离。
15. 作为用户，我希望口头说"免审/不用等我"时代理明确宣告"开始执行 /fn-exempt"再触发流程，以便我看见豁免被正式化而非静默生效。
16. 作为用户，我希望口头豁免也必须记账（tracker 豁免行 + JOURNAL），以便"无记账 = 无豁免"成立。
17. 作为用户，我希望豁免默认只免单门一次，"本批/剩余全部"必须显式声明，以便豁免不被无限放大。
18. 作为用户，我希望每条豁免写明范围、原因、剩余量，用完即标 consumed，以便豁免用量可见。
19. 作为用户，我希望证据类纪律（核验绿了才改、读回断言、失败不记账、无证据=该步未做）永不可豁免，以便豁免只免"等人/审查门"、不造谎报。
20. 作为用户，我希望冲刺模式下门不停人但每步证据照贴，以便提速不牺牲可审计性。
21. 作为用户，我希望豁免不跨技能继承、写明作用对象，以便一次豁免不会意外放行其他门。
22. 作为用户，我希望被豁免放行的每道门在 tracker 上引用对应豁免行，以便事后还原每个门的处置。
23. 作为执行代理，我希望以第一个未勾行为唯一导航，以便执行有确定的"当前步"。
24. 作为执行代理，我希望完成行与函数 commit 同批落账（`· commit` 行例外：证据即该 commit，提交后勾记）、失败不记账，以便账本永远可信。
25. 作为执行代理，我希望出门前自检逐行指认证据位置，以便缺证据的步骤无法宣告完成。
26. 作为执行代理，我希望与计划不符时有明确三态出路（匹配继续/代码错修码/计划错记 Ruling），以便不会"将就着改到输出像对的"。
27. 作为执行子代理，我希望 brief 只含单个任务（机械切片），以便只做被派发的事、不超纲不跳步。
28. 作为执行子代理，我希望回报必须附命令输出原文，以便我的完成声明可被采信记账。
29. 作为审计代理（fn-review / fn-close），我希望有 tracker 核对轴（账本行 vs functions.md 状态 vs git log），以便漂移在终检被拦。
30. 作为审计代理，我希望带病禁行——存在未裁决阻塞项不许进下一步，以便问题不被带病滚动。
31. 作为审计代理，我希望豁免行本身可被逐条核对（范围/期限/是否越权），以便豁免成为审计对象。
32. 作为用户，我希望直接调用 /fn-exempt 与口头触发产出完全一致的记录，以便两条入口殊途同归。
33. 作为跨客户端安装者，我希望 tracker / fn-exempt 规则进 INSTALL.md 修补清单，以便非 ZCode 客户端安装后行为一致。
34. 作为用户，我希望 fn-quick 轻量线保持原样（线别分流不属豁免），以便短路径不变慢。
35. 作为用户，我希望这批改动随版本发布并记入 CHANGELOG，以便版本可追溯。

## Implementation Decisions

**新模块**

- **tracker 账本**（implementation 第四文档）：五节模板——身份行 / 进入五步 / 批次>函数>七步 / 批间门 / 豁免与 Ruling 行。行 schema（源自 grilling 模型稿，编码为契约）：
  - 身份行：`# Implement tracker — fn_docs — 计划: batches.md — 真值: functions.md + git log`
  - 步骤行：`- [ ] <步骤> — 预告: <目标/动作/预期>`；完成后 `- [x] <步骤> — 证据: <命令> → <结果摘要> (<日期>)`
  - Ruling 行：`- Ruling: <偏离内容> — 原因 — 代价 — 落点`
  - 豁免行：`- X<n>: <类型> | 范围: 单门/本批/剩余全部 | 对象: <技能·门> | 原因 | 剩余: N | 状态: active/consumed`（编号 ID 供门行引用与撤销指认；全仓唯一 schema，以 lint 正则为契约）
- **fn-exempt**：独立横向技能（不占阶段位），唯一豁免机制载体。流程：确认豁免类型与档位 → 写豁免行（tracker + JOURNAL 落痕）→ 继续。
- **fn-step-done 硬门脚本**：输入为账本、步骤标识、核验命令；**仅当核验命令 exit 0 才追加 done 行，失败零写入**；写后必须读回贴出改后行。

**升级模块**

- **总纲第五不变式**：步骤纪律的执行载体是 tracker；第一个未勾行 = 当前步；无证据不许勾。
- **fn-implement**：批内七步改为按 tracker 行推进（七步内容不变，判定载体迁移）；预告→执行→证据+读回三段式；完成行与 commit 同刻写入；进入五步第 2 步扩为恢复协议（读身份行 → git log 对账 → 从第一个未勾行继续，已勾行不重做——账本与 git 压倒记忆）；出门前自检改为逐行指认证据；子代理契约加"回报必带命令输出原文，无原文不予记账"（报告不是证据）；原豁免散句（免审/冲刺/预授权/接管 commit）全部删除，原位改为"无有效豁免行 = 不得跳过该门"。
- **fn-analyze**：冲刺模式移交 fn-exempt。
- **fn-merge**：三文档交接铁律补 tracker 移交（新 tracker 从「进入五步」空账起步，旧账不搬运、防旧漂移传染）。
- **fn-doc-lint**：扩展 tracker/豁免一致性校验；**fn-review、fn-close** 各加 tracker 核对轴。

**豁免语义**

- 三档效力：默认**单门一次**；**本批**；**剩余全部**（须显式声明，即预授权连做的口语档）。不自动续期，不跨技能继承；fn-exempt 必须写明作用对象。
- 被豁免放行的门在 tracker 侧引用豁免行；用完即标 consumed（**撤销**：用户明说撤销 → consumed + 一行撤销说明并读回；consumed 带撤销说明 = 主动撤销、无说明 = 额度用尽；撤销后不得再凭该行放行。误触 fn-exempt 而无豁免需求 → 停、声明无豁免发生、回原流程）。
- **永不可豁免**：核验绿了才改、读回断言、失败不记账、"无证据 = 该步未做"。豁免免的是"停下来等人"和"审查门"，永远不免"证据"。
- **口头豁免协议（Q4 加强）**：用户口头提出豁免后，代理的第一动作必须是明确宣告固定语 **"开始执行 /fn-exempt"**，随后才走 fn-exempt 流程（确认档位 → 记账 → 继续）。禁止静默补账，禁止不宣告先干活。

**双真值边界**

- tracker 只记步骤完成与证据指针，**不存函数状态词**；函数状态唯一真值仍是 functions.md。两者唯一衔接点是"清单进位"步——其证据即 functions.md 的读回行。
- Ruling 进 tracker；batches.md 变更记录照旧记计划变更；两者互指不复制。

**移植机制**（源自 superpowers / Mattpocock Skills，逐条对应已采 Q5）

- 账本身份首行 + 每任务一行；失败不记账（task-done 模式）；借口对照表；Expected 比对三态（匹配/代码错/计划错 → Ruling）；brief 机械切片（子代理只领单任务）；带病禁行；"不要信任报告、核验后才记账"。

**发布与可移植性**

- 发版走 release.sh 出 v2.2.0，CHANGELOG 记"追踪器 + 豁免收束"（中英对照：tracker / 执行账本）；INSTALL.md 修补清单补 tracker、fn-exempt、口头豁免宣告语条目；不配 hooks（可移植策略：强制力终点是 workflow 固化）。

## Testing Decisions

- **好测试的定义**：只测可机械判定的外部行为——校验器对构造的 fn_docs 树给出"报错/放行"判定，以及脚本的 exit-code 与写入副作用；不测措辞主观面（措辞由文档评审轴覆盖）。
- **接缝**：**fn-doc-lint 扩展**仍是唯一 lint 接缝（最高、不新增）；行为断言并入 **fn-selftest.sh 验收道次**（构造树可重跑，七断言）。新规则定稿：tracker 五节齐全（身份行 / 进入五步 / 批次节 `## B<n>`——批间门节不算 / 批间门 / 豁免与 Ruling 行 schema）；豁免行全字段（类型五类枚举/范围档位/对象非空/剩余整数/状态）；wired 三方对照（tracker×functions.md 双向 err 级；git 侧**警告级**——commit 文案可被接管 commit 豁免改写，err 级会误伤）。
- **散句残留检索归 release.sh**（退役术语表扩项，整句检索不误伤主题词），不进 fn-doc-lint——散句是本仓库的回归防线，与用户项目的 fn_docs 无关。
- **待测模块**：fn-doc-lint 新规则、fn-step-done 副作用契约（失败零写入/成功落账读回/重复拒绝）、release.sh 退役术语扩项、fn-selftest 自身。
- **先例（prior art）**：fn-doc-lint 现有交叉校验（状态词正则、批次/历史不重叠、矩阵双向、functions×code 桩标记交叉）、release.sh 退役术语表、fn-check 三件套。

- fn-quick 轻量线改造（线别分流不属豁免）。
