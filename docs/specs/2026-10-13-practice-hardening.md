## Problem Statement

实践暴露两类收益点未进技能：①需求/责任颗粒度更细时实现不遗漏（20R→55R、顶层↔R 一一对应、叶子单一转变），但技能缺可执行的拆条判据，且"长职责该不该拆"无定论；②批间子代理对抗性审查（假设文档是错的、命令会失败）能抓出脆弱断言/死链/永不触发/误导说明四类普通自测难现的问题。另有两条流程缺口：实施无虚拟环境（污染全局、后续测试无环境）；终检无面向用户的使用手册与"模拟用户走查-修复"闭环。

## Solution

- **颗粒度铁律**：fn-grill"一条 R = 一个功能"（独立验收/修改/映射）；fn-divide"叶子职责 = 单一功能转变；长职责 ≠ 必须拆（纯编排不拆），判据 = 是否内联多个不相干转变"；顶层↔R 默认一一对应（例外注明）；fn-doc-lint warn 点名长职责（>160 字）人判定性。
- **批间对抗审查**：每批并行新增独立对抗审查子代理（与三轴评审分离），契约六要素（只读/逐字实跑/原文贴输出/临时件只落 /tmp、仓库零写入/对抗假设/校验工具在审列），发现分级 Critical/Important/Minor，**Critical 清零不过门**，修复走白名单子代理 + scoped 复审。
- **虚拟环境**：fn-implement 进入即建/验环境（fn_work/.venv 或等价），依赖清单入库为真值、环境保留可重建；测试/核验一律经环境；禁污染全局。
- **用户走查环**：fn-close 新增独占产出 user-guide.md（环境配置/快速开始/使用方法/已知限制），六道之后走查环：模拟用户逐条实跑 → 对抗发现表 → **显式派子代理执行 fn-implement 修复**（遵守其文档更新纪律）→ 回主对话重走查，至清零（**Critical/Important 清零，Minor 留档注明**）；单环 5 轮封顶超限报用户；文档类问题指回 owning 阶段。环清零后六道全量重跑 + 重写验收报告。

## User Stories

1. 作为用户，我希望 R 条目按"一条一功能"拆到可独立验收/修改/映射，以便实现不遗漏、审改单点化。
2. 作为用户，我希望顶层函数与 R 默认一一对应，以便映射链可审计。
3. 作为划分者，我希望长职责被点名复查但不强拆（编排 ≠ 混职），以便不过度拆分。
4. 作为用户，我希望每批有一次对抗性审查（假设文档是错的），以便抓出脆弱断言/死链/永不触发/误导说明。
5. 作为用户，我希望对抗发现 Critical 未清零不过门，以便问题不被带进下一批。
6. 作为用户，我希望实施即建虚拟环境、依赖清单入库，以便全局不被污染、换机可复建。
7. 作为用户，我希望测试/核验一律经环境执行、环境保留，以便后续测试口径一致。
8. 作为用户，我希望终检产出使用手册（含环境配置说明），以便交付即可用。
9. 作为用户，我希望手册经模拟用户逐条实跑走查、修复循环至清零，以便真用户第一次上手不撞坑。
10. 作为用户，我希望走查修复显式派子代理执行 fn-implement（含文档更新纪律），以便修复不破坏档案同步。
11. 作为用户，我希望走查环 5 轮封顶超限交我裁决，以便不无限打转。
12. 作为审计者，我希望校验工具自身也在对抗审查之列，以便脚本 bug 不漏网。

## Implementation Decisions

- fn-grill：R 模板注记拆条铁律 + 可选"参考映射"行（指向参考资料条目号，审哪条看哪条）；出门自检补"R 逐条过一功能判据"。
- fn-divide：划法规则 1 补"顶层↔R 默认一一对应（例外注明承载方式）"；规则 3 补"长职责 ≠ 必须拆——纯编排（每步已下探子函数）即单一转变，判据始终是是否内联多个不相干转变"；产出前自检第三条补长职责人工定性。
- fn-doc-lint：`- 职责：` 行 >160 字 warn 点名（启发式只 warn 不 err——校验脚本自身也会有 bug 的教训）。
- fn-implement：进入五步第 1 步扩"环境在位"（建/验 venv、依赖清单装齐、记 tracker 证据）；批间门并行加对抗审查子代理（契约六要素 + 分级 + Critical 清零 + 白名单修复 + scoped 复审 + 误报申诉归用户）；tracker 批间门节加"对抗审查"行；核验命令一律经环境执行。
- FN-LADDER：目录契约加"环境隔离区"（依赖清单入库为真值、.venv gitignore 保留可重建）；子代理清单加 ④ 对抗审查子代理；所有权表 fn-close 行扩"user-guide.md 使用手册"。
- fn-close：产出扩为 acceptance.md + user-guide.md（模板四节：环境配置含复建命令 / 快速开始 / 使用方法逐条实跑 / 已知限制）；六道后"用户走查环"独立环节（走查者只读、修复者 = 显式子代理执行 fn-implement、文档类指回 owning、手册错漏本阶段直改；每轮复走查只核修复面；清零后六道全量重跑重写报告；5 轮封顶）；⑥ 加"依赖清单齐、环境可复建"。
- fn-check.sh：头注"经虚拟环境执行"，存在 `fn_work/.venv` 时自动激活。
