## Problem Statement

自动化场合（冲刺门不停人 / analyze 冲刺 / 预授权连做 / 走查修复环自动循环）存在合并简化的系统性诱惑：两审查合一子代理、多函数一锅出报告、批级测试顶替逐函数测试、三段式压缩、修复与复审合一、跨批攒批过门——收益是 token，代价是审查视角互相稀释、证据粒度塌缩，正是跳步病在自动化下的复发形态。

## Solution

新增横切"自动化纪律"：适用一切"免人"场合；**推进单位=批**（过门自动开下一批、批间报告照发）；批内可连续推进但每动作**独立原子**（独立派发/独立证据/独立记账）；合并禁令总则"**一个步骤一个动作一份证据、一类审查一个子代理、一批一轮一交付**"+ 示例表；走查修复环三动作（走查/修复/复走查）不得合一；豁免协议补"豁免免停、不免步骤"；违规并入第五不变式"合并/跳步"同款处置。

## User Stories

1. 作为用户，我希望自动化只按批推进（过门自动开下一批），以便节奏可控、批间报告照发。
2. 作为用户，我希望自动化 = 免人等待 ≠ 免步骤，批内每动作独立原子，以便效率与证据粒度兼得。
3. 作为用户，我希望三轴评审与对抗审查永远两个子代理（自动中也不例外），以便审查视角不互相稀释。
4. 作为用户，我希望合并禁令有总则+示例表，以便新姿势绕不过、老姿势有判例。
5. 作为用户，我希望走查修复环的走查/修复/复走查三动作不得合一，以便自动循环不糊成一团。
6. 作为用户，我希望豁免免停但不免步骤，以便豁免不被钻成简化通道。
7. 作为审计者，我希望合并简化按第五不变式"合并/跳步"同款处置，以便违规有判例可依。
8. 作为执行者，我希望"连续做"合法而"糊着做"违规，以便边界清晰不误伤效率。

## Implementation Decisions

- FN-LADDER 新增"自动化纪律"小节（三要素：推进单位=批 / 批内连续但原子 / 合并禁令总则+示例表；走查环三动作分立条款；判例指向第五不变式）。
- 豁免协议补固定句"**豁免免停、不免步骤**：豁免只免被明文豁免的那道门/审查；**其余动作一个不少、一个不合并**——豁免不许成为合并或压缩保留动作的理由（定点删除合法，批量稀释违法），自动化纪律照常全效"。
- 第五不变式补判例括注（自动化场合的步骤合并/审查合一同属"合并"，处置同款）。
- fn-implement 冲刺例外句补"自动化不免步骤——推进遵守 FN-LADDER 自动化纪律（两审查恒分立、每函数七步照走，禁止合并简化）"；fn-analyze 冲刺节补"步骤不合并"引用；fn-close 走查环补"三动作不得合一"。
- README×2 补一句；示例表可经改版增补。

## Testing Decisions

- 无新机械规则（纪律类约束由第五不变式与审计轴承载）；selftest 9/9 + release --check 保持即验证。

## Out of Scope

- 轻量线改造（无免人模式）；合并检测器自动化（判定归审计轴）。
